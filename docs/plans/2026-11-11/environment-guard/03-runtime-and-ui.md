# 阶段 03：常驻保护与菜单栏客户端

## 阶段目标

运行中网络变化触发重验与准确处置，菜单栏、详情和终端对保护状态给出一致解释。

## 进入条件

阶段 02 门禁通过，决策和进程登记已有可验证协议。

## 范围

事件采样、会话管理、信号序列、SwiftUI/AppKit 菜单栏/设置、通知、历史与 onboarding。

## 非目标

跨设备、系统扩展、浏览器指纹、自动修改用户地理或支付资料。

## 当前证据

参考产品设计与 interface 文档；实际进程身份来自阶段 02，不能按显示名称识别。

## 设计与实施方案

实现网络事件、配置/时区/语言变化、唤醒和周期回退；先使快照失效，再串行化同一 context 的动作。所有信号前验证 UID/PID 启动时间/可执行身份。停止状态的进程在退出前恢复，让 SIGINT 能被处理。5 秒未完成必要复核按契约退出，恢复稳定 30 秒后解除闸门但不自动重开。

先用 `design-taste-frontend` 重读平台方向，再按原生设计构建界面。显示“安全分，越高越安全”和“检查完整度/保护覆盖”，逐项列扣分；多上下文取最严格状态，未受管会话独立展示。检查列表真实显示适用、通过、触发、缺失与未支持数。

## 测试方案

用模拟 Claude 进程和旁观进程验证 PID 重用、共享 shell 进程组、忽略信号、嵌套进程、无关同名进程；旁观进程必须保持存活。断网/换网/睡眠/代理关闭/规则变化/检测源超时/恢复均做端到端回放。

验证多个上下文不串分，UI 与 terminal reasonCode 一致；退出 UI 后 Agent 仍工作；Agent 停止时 UI 不显示旧安全状态。

验证纯轻微扣分累计至 79 分时，新启动和运行中会话均执行阻断，无“只有网络重项才能退出”的隐藏条件。

## 输出契约

原生 App、运行中处置事件记录、实际截图及可复现验收脚本，证据保存 `docs/validation/phase-03/`。

## 完成门禁

全部关键状态可复现；无非目标进程受信号；硬风险立即开始处置；普通抖动按防抖；通知关闭仍能解释结果；界面可访问。

## 交付物

可交互菜单栏 App、持续监测/退出策略、会话与历史界面、运行时与视觉证据。
