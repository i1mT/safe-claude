# Claude 环境防护调研

调研日期：2026-11-11，Asia/Shanghai。

## 结论与产品取舍

用户描述的“启动前检查 + 常驻监测 + 条件触发退出”采用菜单栏 App、独立 Agent 和 launcher 实现。2026-11-11 用户已明确：保守防护、所有可持续采集的相关项计分、安全分越高越安全。

最有价值的检测对象是**实际 Claude Code 进程的网络路径、配置完整性、出口变化和防护覆盖状态**。菜单栏 App、终端、IDE、后台任务可能使用不同路径。浏览器检测页的结果不能直接代表 CLI。

本报告分四类证据：

| 类别 | 含义 | 产品用途 |
|---|---|---|
| A | 官方文档或明确公开政策 | 适用范围校验、兼容实现依据 |
| B | 能在本机重复测量的事实 | 检测异常；异常与封号的因果关系另行说明 |
| C | 社区经验、个人陈述、第三方分类 | 转为可采集检查项，按权重扣分，参与阈值动作 |
| D | 本产品的启发式设计 | 阈值和权重，明确没有统计校准 |

证据分类作为来源元数据，不作为排除计分的门槛。当前产品取舍以 [64 项检测清单](../design/check-catalog.md) 与 [评分契约](../design/scoring-and-policy.md) 为准；以下历史材料保留来源便于维护。

## 官方可以确认的事实

### 封号原因与账号状态

官方申诉说明列出重复违反使用政策、在不支持地点创建账号、违反服务条款等原因，没有公开 100 分积分公式。[S1]

工具应区分网络超时、登录失效、容量限制、组织 hold、账号禁用。单个 401/403 或验证码不能直接确诊“账号被封”。V1 不主动调用账户接口验证账号状态，不读取凭据；若未来导入用户选择的诊断记录，仍需分类与脱敏。

### 地区政策必须带时间

调研时官方地区政策页面显示生效日为 **2026-11-12**，比本次调研日期晚一天。其文字覆盖实际身处不支持地区、相关实体注册/总部、所有权或控制等情况。[S2]

这份即将生效的政策必须单独保存，不能在 2026-11-11 提前作为现行规则。2026-11-11 可参考官方帮助中心地区清单及已有封禁说明；清单核对时中国大陆、香港、澳门未被列出。[S1][S3]

出口落在支持地区不等于实际使用人或实体符合要求。IP 只能作为网络观测；所在地/实体条件只能由用户声明和官方指引补足。产品不提供地理伪装或自动切换出口来绕开地区限制。

### Claude Code 支持代理，也正式支持 Linux

官方网络文档支持 HTTP/HTTPS 代理、`NO_PROXY`、企业 CA 和 mTLS，明确不支持 SOCKS 代理。当前文档的代理优先级为 `https_proxy`、`HTTPS_PROXY`、`http_proxy`、`HTTP_PROXY`，且不同宿主/设置作用域有区别。[S4] 产品按用户选定的保守策略，给代理、机房等属性低权重，给路径异常和信任配置变化更高权重。

官方安装文档支持 macOS、Windows 和多个 Linux 发行版。[S5] E09 不把 Linux 本身当作风险，而检查 SafeClaude 所在 Mac 是否运行于支持版本及内核报告的 Hypervisor 来宾状态。XNU 中 `kern.hv_vmm_present` 在 arm64 读取设备树标记，在 x86_64 读取 CPUID VMM 位，并归一化为布尔值；读取失败保持 unknown。[S19] OpenSSH 为远程 shell/命令设置 `SSH_CONNECTION`、`SSH_CLIENT` 和可选的 `SSH_TTY`；SafeClaude 仅验证字段结构并记录命中布尔值。标记来源于进程环境，只作为 3 分启发式，不当成可防篡改证明。[S20] 两类信号均不推断未观测的远端机器环境。

### 官方已经提供进程包装入口

官方 corporate launcher 文档提供：[S6]

- `CLAUDE_CODE_PROCESS_WRAPPER`：要求 v2.1.208+。
- `processWrapper` 设置：要求 v2.1.210+。
- Remote Control、agent teams 等部分路径还要求 v2.1.210+。
- 旧版可能静默忽略设置，必须用功能验证确认。
- 单纯 PATH shim 覆盖不了内部以绝对路径启动的后台服务。
- 包装器应最终 `exec` 原命令、保留 argv/env/cwd、不读 stdin、不污染 stdout，约三秒内交接。
- 官方建议在 PATH 更前面的独立目录放 shim，**不要替换原安装器维护的链接**。
- 深链接、某些 tmux 路径、浏览器 native messaging 等有明确覆盖缺口。
- 常驻后台服务不会重新读取 shell 配置；配置变更需要检查已有服务并引导重启。

这是首版的重要集成方式，但不是全系统不可绕过的执行拦截器。

### 凭据和发行边界

官方文档区分 Claude Code 的正常原生 OAuth 使用和第三方代用户路由订阅凭据的行为。V1 只包装用户自己安装的官方命令，不修改二进制，不接管 OAuth，不把订阅变为转发服务。[S7]

官方同页对名称和标识有约束。仓库可暂用 safe-claude；公开发行前采用独立品牌并复核商标使用，不使用 Anthropic/Claude 标识暗示官方背书。[S7]

## Net.Coffee 页面实际做了什么

已用 HTTP 获取页面和它直接引用的 `claude-page.js?v=20260916a`，没有操作浏览器。[S8][S9]

| 页面模块 | 静态代码观察 | 对本产品的启发 |
|---|---|---|
| Claude 出口 | 请求 `claude.ai/cdn-cgi/trace` 并读取 `ip`、`loc` | 比普通 IP 检测更接近该域名路径，但不能代表所有 API 域名 |
| Trust Score | 来自后端 `trust_score` | 后端权重未公开，无法还原或验证封号预测能力 |
| 地区限制 | 前端维护一组地区代码，命中时将分数设为 0 | 不复制其静态名单；用官方、带日期的适用范围 |
| IP 属性 | ASN、住宅/机房、VPN/Proxy/Tor、滥用等 | 可作可插拔第三方信誉信息 |
| DNS | 通过测试域名、结果 API 归集解析器信息 | 解析器出口不同不等于 Claude HTTP 请求出口不同 |
| WebRTC | STUN 与浏览器 `RTCPeerConnection` | TCP/UDP 一致性可转为原生诊断 C07；不依赖浏览器 |
| 设备指纹 | 浏览器时区、语言、Canvas/WebGL 等 | 时区/语言/区域转为进程与系统一致性 E 类；Canvas/WebGL 留待浏览器范围 |
| 可用性 | 请求站点、时间测量与站点服务状态 | 区分服务故障与环境异常，不把所有异常归为封号 |

脚本注释声称后端评分按 CIDR 计算、缓存 365 天；这只是客户端注释，未验证后端真实实现。页面未公开可商用的稳定 API 契约，内部 `/api/iprisk/{ip}` 不能直接作为本产品的生产依赖。

`/cdn-cgi/trace` 属于诊断信号，未见对本产品保证可用的 API SLA。`loc` 不应直接当作精确所在地证明。任何诊断路径都可能被分流、禁用或限速；失败须为 unknown。

**重要限制：**第三方站点请求某个 IP 的信誉只能说明其数据库分类；网站服务器代发请求不能测量用户 Claude 进程的真实出口。信誉查询与出口探测必须分开设计。

## 用户提供的 X 积分表：18 项逐项处理

原帖时间为 2026-10-28 04:05 UTC。X 直接读取返回 403；通过 FxTwitter JSON 镜像取得文本与时间，属于第三方转交内容，未获得 Anthropic 官方确认。[S10]

下面是分析性摘要及修订后的实现取舍。可持续读取的相关信号全部计分；不能持续取得的账户资料排除。

| 原帖项 | 概述 | 可观测性与证据 | V1 处理 |
|---|---|---|---|
| 1 | 内部用积分和封号线 | 输入需转为本产品可读检查 | 100 分扣减制，低于阈值启动/运行中统一阻断 |
| 2 | 邮箱、注册 IP、注册渠道和 KYC 影响起分 | 注册资料无法持续核验 | 排除历史资料；当前出口/地区按 A/B/C 计分 |
| 3 | 订阅时机、方案与验证影响评分 | 无持续本地状态来源 | 排除支付/KYC/订阅时点 |
| 4 | 出口应稳定并启用 TUN/全局 | 实际路径和变化可测 | A/C/D 检测真实路径、分流与稳定性并扣分 |
| 5 | 老账号更耐受 | 无可靠账号创建时间来源 | 排除账号年龄；不拿安装年龄代替 |
| 6 | 耗尽额度和不同客户端影响积分 | 账号级用量不可读，本机活动可采集 | G 类计并发、启动、错误/重试、多客户端 |
| 7 | 时区和语言影响很小 | 系统、进程和 IP 元数据可测 | E 类低权重扣分，分别检查时区、语言与区域 |
| 8 | 并发、重复提问、频繁登录和换 IP | 可采本机会话、变化及诊断计数 | C/G 类全部计分；重复问题正文不读取 |
| 9 | 移动端、记忆带来加分 | 手机使用不可读；本机记忆状态待适配 | G07 对可读的关闭/空记忆状态扣分，不读正文 |
| 10 | 不同支付渠道有分数差异 | 无持续采集来源 | 排除支付资料 |
| 11 | 观察期与隐含分数线 | 可采本机错误和认证失败 | G03/G04 按可读的状态计数扣分 |
| 12 | 多设备登录大幅扣分 | 本机可见客户端/会话，其他设备不可见 | G01/G05 本机并发/多客户端扣分 |
| 13 | 虚拟机/远端环境 | 本机内核虚拟化信号可持续采集；远端环境不可从本机确认 | E09 对内核识别的虚拟机低权重计分；远端执行保持待补检测 |
| 14 | 自报国籍/记忆内容无影响 | 正文不属采集范围 | 排除正文；语言、区域和记忆状态分别采元数据 |
| 15 | 购买 Credits 加分 | 无持续本地余额/账单来源 | 排除 Credits |
| 16 | 某模型的大量使用扣分 | Fable 的官方模型资料见 [S15]；当前模型需状态适配 | G06 对可读且命中关注清单的当前模型低权重计分 |
| 17 | 升级 Max 引发观察期 | 无持续本地升级时点来源 | 排除订阅变化；可见认证失败仍按 G04 |

## 扩展调研：哪些值得检查

1. **实际生效的代理配置**：大小写变量优先级、`NO_PROXY`、用户/项目/托管设置、启动宿主差异。[S4]
2. **目标域名分流**：身份验证、token 交换与模型 API 涉及多个域名，检测不能只看 claude.ai。[S4]
3. **IPv4/IPv6 路径不一致**：A06 对额外双栈路径低权重扣分，对绕过声明路径高权重扣分。[S8]
4. **出口稳定性**：按国家、ASN、IP 分层记录，避免把移动网络/IPv6 隐私地址正常变化等同跨区跳变。与封号因果关系未经校准。
5. **信誉标签**：Tor、已知恶意/滥用、机房、VPN、共享/住宅代理全部按 B 类权重扣分。
6. **TLS 与代理可达性**：可查证书验证是否被显式关闭、配置的代理是否不可达；企业自签 CA 不自动扣分。[S4]
7. **集成健康**：shim 顺序、绝对路径绕过、后台服务配置漂移、官方升级和版本兼容。[S5][S6]
8. **服务故障**：影响必要路径检测时执行完整度扣分和 hold，修复后重验。

关于时区检测讨论，检索找到 `@trq212` 在 2026-06-30 的实验回滚回复，HTTP 镜像取得文本。[S11] 当前产品按用户确认方向，持续检测时区、语言、区域与出口的一致性，并纳入 E 类扣分。

## macOS 系统能力边界

`SMAppService` 可在 macOS 13+ 注册和管理登录项、LaunchAgent/LaunchDaemon，并有系统批准状态。[S12] 推荐首版用户级 LaunchAgent，不引入 root 常驻服务。

更强的执行前拦截应评估 Endpoint Security；其 entitlement 必须向 Apple 申请。[S13] Network Extension 可以允许或拒绝网络连接，但属于另一类系统扩展与分发/权限设计。[S14]

普通进程监测加信号存在“检测到之前已发送请求”的时间窗口。即使有 Network Extension，也要验证既有连接、缓冲数据和规则生效时间，不能宣称消除所有竞态。

## 未解决的研究问题

- 官方包装入口的版本描述已确认，但没有在本机安装、运行或修改 Claude；兼容与计时必须在阶段 01 验证。
- Net.Coffee API 商用许可、速率与完整评分公式未取得。
- ProxyCheck v3 `operator.services` 可标出运营方服务类别，但这只说明运营方提供某类服务，不能证明查询 IP 本身就是住宅代理节点。官方 OpenAPI 还定义了 `device_estimate.address` 和 `.subnet`，描述为该 IP 及所在子网的估算设备数，并说明异常高估算可提示开放代理/VPN。SafeClaude 以 `address >= 25` 作为 B07 辅助扣分启发式；该阈值由产品设定，供应商未给阈值。B07 仅接受 `last_updated` 不超过 15 分钟的底层记录；缺失或过期时间戳不计此信号。该信号仍不能确认 P2P 属性，规则保持 unknown/hold。ProxyCheck 建议匿名 IP 结果最多缓存 15 分钟，SafeClaude 将该上限用于所有 v3 响应。
- 通用 HTTPS 检测目标无法证明所有目标域名出口；无自有观测端/代理集成时必须降低覆盖置信度。
- 规则评估采用本地可重放场景，逐条核对采集成功、触发、权重、去重与处置。
- 多账号、多设备、服务端支付/身份状态不在本机首版的可靠可见范围内。
