# 评分和阻断契约

版本：`draft-2`；2026-11-11。用户已确认高分更安全、全量可采集信号计分和保守阻断方向；具体初始权重如下。

## 产品准则

1. 安全分 `S` 从 100 开始扣减，0–100，越高越安全。
2. 可持续检测的相关项全部进入评分。轻微信号低扣分，严重异常高扣分；原“只提示”的项目同样计分。
3. 没有官方确认不构成排除条件。来源只决定维护优先级与初始权重，不决定该项能否触发阈值动作。
4. 支付方式、注册渠道、账号年龄等无法可靠持续取得的资料不纳入。不以手填、猜测或磁盘文件创建时间替代。
5. 多项轻微扣分可以累计到阻断阈值，也可以触发运行中退出，不另设“必须有严重网络项”的限制。
6. 所有检查按此次 Claude 的有效配置、实际进程和网络路径执行；菜单栏 App 的观测只用于明确标注的本机上下文。

## 64 项规则与组织方式

完整定义见 [检测项清单](check-catalog.md)，包含 64 个独立规则 ID、触发条件、初始扣分、采集输入与适用前提。8 个栏目用于导航，不是 8 个检查，也不设整组分数上限。

| 栏目 | 数量 | 内容 |
|---|---:|---|
| A 出口与实际路径 | 10 | 地区、代理、目标分流、IPv6、NO_PROXY、网关 |
| B IP 属性与信誉 | 8 | Tor、滥用、共享代理、VPN、机房、信誉综合值 |
| C 连续性与变更 | 8 | 国家/ASN/IP 变化、地理跳变、会话内变化、TCP/UDP |
| D DNS 与传输 | 8 | 解析路径、解析器归属、降级、TLS、证书 |
| E 本机与出口一致性 | 10 | IP/时区/语言/区域、进程环境、系统时间、运行系统 |
| F 配置与防护完整性 | 8 | 有效设置冲突、版本、二进制、wrapper、shim、信任配置 |
| G 本机使用与客户端状态 | 8 | 并发、启动频率、重试、登录失败、多客户端、模型、记忆 |
| H 检查完整度 | 4 | 缺失、过期、来源冲突、历史不足 |

没有为凑数量新增独立“正常奖励”。安全分不通过购买、账号资历或其他无关正项抵消已发生的扣分。

## 计算公式与去重

```text
deductions = sum(weight(rule, observedSeverity) for independentTriggeredRules)
safetyScore = max(0, 100 - deductions)
```

数值经规则内定义处理后取整数。**不再给四个大组分配固定额度，也不把不同机制的异常压成一条提示。**

去重只处理重复观测：

- 相同出口的同一标签被两个供应商命中：一项扣分，两个证据。
- 同一次国家变化附带 ASN/IP 变化：以该事件最高级变更规则扣分；频繁变化用规则的升级档替代低档。
- IP/时区不一致与 IP/语言不一致属于不同检查，分别扣分。
- 代理/VPN 与机房分类是不同属性，可累积；供应商综合信誉若已经包含这些分类，不与其拆分项重复加总。
- 同一字段缺失只触发一次完整度扣分，不给每个依赖它的规则重复扣“缺失”分。

每条 deduction 记录 `ruleID`、`observationIDs`、`eventID`、`mechanismKey`、`supersedes`、`points`，回放可逐项重算。

## 采集状态

每条规则使用以下状态，不能把读不到自动当作通过：

| 状态 | 含义 | 计分/决策 |
|---|---|---|
| pass | 适用且采集完成，未触发 | 该项扣 0 |
| triggered | 适用且满足触发条件 | 扣清单定义的分值 |
| unknown / stale | 已启用项暂时不可读或过期 | H 类扣分；默认 hold |
| not_applicable | 当前场景无此机制 | 不扣分，写明原因 |
| unsupported | 当前版本没有通过验证的采集适配器 | 显示未支持；必要能力缺失则 hold |
| excluded | 无法持续取得的产品范围外资料 | 不进入当前激活规则集 |

适用性由能力发现和验证过的适配器决定，不由用户随意勾选“不适用”绕过。比如没有 IPv6 路径时不执行 IPv6 出口规则；启用了 IPv6 而探测失败是 unknown。

64 是规则目录规模。每次评估输出准确的总数、适用数、完成数、触发数、缺失数和未支持数。目录中的候选适配器在阶段 01 验证；不能读取的模型/记忆/诊断字段不编造结果。

首次安装的历史不足独立扣 3 分，不要求等待 24 小时才能使用。只针对未知的历史项执行此规则一次，当前路径与一致性检查仍必须完成。

## 输出数据契约

```text
SafetyResult
  safetyScore: Int?              # 完整且可决策时为 0–100
  scoreUpperBound: Int?          # 检查未完整时，当前扣分得到的安全分上界
  knowledge: complete | partial | unknown
  protection: covered | partial | unavailable
  totals: catalog / applicable / completed / triggered / missing / unsupported
  deductions[]
  checks[]                      # 含通过项与不适用原因，不能只输出异常
  ruleVersion / policyVersion
  observedAt / expiresAt
  networkEpoch / contextID
```

未知时菜单栏显示 `—`，详情可显示“已知扣分 11，安全分上限 89；另有 2 项待检测”。不能把上界 89 当作可放行分数。

## 默认阈值与动作

默认保守配置：

- `S >= 90`：允许启动。
- `80 <= S < 90`：允许启动，显示扣分原因。
- `S < 80`：阻止新启动；运行中会话立即进入保护处置。
- 恢复要求 `S >= 90`、所有必要检查完成，连续稳定 30 秒；不自动重启已退出会话。
- 启动最低安全分与运行中最低安全分均可单独设置，默认都为 80。

恢复最低分默认按 `min(100, max(启动最低分, 运行中最低分) + 10)` 联动计算，初始为 90；不能因调高阻断阈值而出现“恢复放行分反而更低”。单独修改恢复阈值时也验证其不低于两个阻断阈值。

比较运算为**低于**：79 阻断，80 允许但有提醒。界面统一写“低于 80 分时阻止启动”。

决策优先级：

1. 命中硬规则 → deny；分数同时按该项扣减。
2. 已启用检查缺失/过期、配置无法解析或必要入口未覆盖 → hold。
3. 完整安全分低于设定阈值 → deny。
4. 其余按区间 allow / warn。

不再区分“提示项只能提示、不能导致退出”。时区、语言、机房、并发等扣分只要使总分低于阈值，就执行同一阻断策略。

## 运行中保守处置

```text
checking -> allowed / warning / holding / blocked
allowed + network/config-change -> holding
allowed + score-below-threshold -> holding
holding + confirmed-below-threshold -> terminating -> blocked
holding + complete-and-passed -> allowed / warning
blocked + sustained-recovery -> allowed
```

网络或有效配置变化立即使旧结果失效，禁止新启动，并对已受管会话发起暂停。已确认硬规则直接开始退出；普通越线在暂停下进行一次快速复核，不继续运行等待防抖。

运行中 5 秒内仍无法完成必要检查，默认开始退出。该时间为错误恢复预算，可设置 0–5 秒；不是继续使用宽限期。

退出序列沿用已接受方案：确认 UID、PID 启动时间和 executable；必要时先 `SIGCONT` 再 `SIGINT`；2 秒后仍存活发 `SIGTERM`；再 1 秒未退出，按预设“强制终止”选项追加 `SIGKILL`，否则明确显示退出失败。绝不向共享 shell 进程组或仅同名的无关进程发信号。

## 完整度与故障

| 条件 | 分数/原因 | 默认行为 |
|---|---|---|
| 出口处于不支持地区 | A01 扣 100 | deny，运行中立即开始退出 |
| 锁定代理断开 | A02 扣 40；实际出口待查则同时标缺失但不重复扣同根因 | hold / deny，不回退直连 |
| IP/时区不符 | E01 扣 6 | 参与所有阈值动作 |
| IP/语言不符 | E03 扣 3 | 参与所有阈值动作 |
| 信誉供应商超时 | H02 扣 5，显示未完成 | hold，不沿用过期高分 |
| 必要来源相互冲突 | H03 扣 10，显示待复核 | hold |
| Agent 不可用 | `—`，保护不可用 | 新启动 hold；恢复后立即重验已登记会话 |
| 官方服务故障导致目标探测不可完成 | H01，路径检查待完成 | hold；不另添加一条“账号异常” |

## 权重维护与验收

规则维护者可依据社区经验增加检查项、提高或降低权重。发布要求有采集说明、可重复触发夹具、作用域、去重关系、阈值回放和回滚版本。

测试至少覆盖：纯轻微项累计至 79 时仍退出；79/80/89/90 边界；缺失不放行；IP/时区和 IP/语言独立计分；多供应商同标签不重复；同一变更事件升级替代；规则更新影响已有会话；恢复不自动重启。
