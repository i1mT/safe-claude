# 界面与交互设计

2026-11-14；安全分与 UI 视觉重设计版，2026-11-14 设置控制台续修，2026-11-14 仪表盘刻度环改版。使用 SwiftUI/AppKit 原生交互能力，建立 SafeClaude 自有视觉层级，而非直接沿用系统默认菜单和表单排布。

## Design Read

面向日常使用 Claude Code 的开发者，做一眼可判断状态、细节可追溯的 macOS 安全工具。视觉以系统适配的中性石墨表面、SF 系统字形和原生导航行为为基础；SafeClaude 青柠只用于品牌和主操作，安全/风险文字使用适合当前外观的高对比语义色。遵循 macOS 浅色、深色和增强对比外观，不把整套窗口锁死为深色。分数与明确结论构成主层级，规则证据以简洁行和样本时间承载；减少胶囊徽章、层叠圆角卡片、英文 kicker 与装饰分隔线。保留菜单栏、键盘、窗口和辅助功能语义。

平台参考：[Apple MenuBarExtra](https://developer.apple.com/documentation/swiftui/menubarextra) 对信息量较大的菜单栏内容建议采用 window 样式；[SwiftUI 菜单栏指南](https://developer.apple.com/documentation/swiftui/building-and-customizing-the-menu-bar-with-swiftui) 作为场景、键盘命令与设置窗口的实现参考。

设计参数：`DESIGN_VARIANCE=6`，`MOTION_INTENSITY=3`，`VISUAL_DENSITY=4`。按开发者安全工具和信任优先场景选择低动效、适中密度；通过排版、留白和一致输入反馈形成识别，不加无语义装饰。

菜单与设置共享随系统外观变化的中性画布、表面、分隔线和文字颜色；盾牌标识使用青柠底色。主面板安全分以开放式 48 刻度弧环呈现，真实分数置于中心；分数与结论优先，刻度随后。弧环不是覆盖率或检查完成度。信息不全时仅弱化显示安全分上限对应的刻度，中心仍显示 `—`，旁边直接注明这是上限且必要检查完成前不会放行。以系统分隔线组织环境信号，避免小面板里重复嵌套卡片。SF 系统字形、等宽状态数字和 SF Symbols；颜色始终与文字/图标共同表达状态。动效仅用于分数与刻度更新，并遵守减少动态效果设置。设置页使用原生侧栏选择、清晰页面标题和简短说明，不使用网站式大写栏目眉题；输入焦点提示使用系统可读的强调色。

操作按钮按可用状态表达层级：主操作使用青柠填充，次操作使用石墨表面与描边，危险操作使用珊瑚文字；操作被禁用时统一降为中性灰字与石墨表面，并移除按压缩放反馈，避免忙碌或条件未满足时仍呈现可执行的强调态。菜单底部“立即检测”、集成管理、设置和全量报告共用同一套主/次按钮状态语言。

## 菜单栏状态与安全仪表盘

视觉修订：将安全分从普通内容卡中抽离为“仪表面”——固定的深石墨绿底、白色主数字、单一青柠通过色和明确的琥珀/珊瑚风险色。该区域在浅色系统外观中形成稳定焦点，在深色外观中与画布融为一体；其余内容仍跟随 macOS 外观。仪表不依赖模糊、透明叠层或光晕，增强对比模式使用纯黑底与纯白主文字。保留 20 段短刻度，将安全分与本次决策绑定，避免把装饰性圆环误读为检查覆盖率。

正常：盾牌 + `94`；提醒：盾牌 + `86`；阻断：盾牌 + `77` 并有阻断标记。数据不足显示 `—`，采样显示 `…`，Agent 停止显示 `!`，不能继续显示旧绿色分数。最近一次 Claude 启动检查结果最多保留 5 分钟供菜单栏展示；受管会话状态优先展示。面板和全量报告要标明分数来自最近启动检查、受管会话或后台默认采样。

弹出面板使用约 420×650pt 的自适应系统外观：品牌与 Agent 状态在顶部；安全分刻度环与状态/门槛组成并列主区，刻度环适配系统文字缩放，右侧直接给出本次上下文的结论和恢复方向；读数区标明最近样本时间；其后按扣分列出最重要的环境信号，再显示待确认数、受管会话数和最近检查。底部主操作独占一行，集成、规则和设置作为带图标与文字的次操作排列在下一行。

必要检查未完成时菜单栏和大号分数都显示 `—`，不把安全分上界伪装成实得分；刻度环仅弱化呈现上限。面板直接说明这是上限，信息补齐前不会放行，展开列表显示待确认项目。达到门槛或阻断时，主区直接显示本次上下文对应的启动/运行门槛数值；运行中门槛与新启动门槛分别标明。状态摘要用明确数字显示待确认项，避免把“完整”放在“待确认”标签下造成歧义。Agent 不可达和状态过期有独立错误说明及重新连接操作，不能继续展示旧绿色分数。开启“减少动态效果”时，分数刻度不执行动画。

当前界面中的 finding 列表是预览，不代表全量检查报告。独立 64 项规则窗口可按 A–H 分类浏览并查看触发扣分、风险已触发但仍有检查缺项、已通过、不适用、未知、不支持、缺少观测或后台未报告。报告顶部汇总风险项、待确认项、已通过项和已报告数量；这些是规则状态计数，不合并成误导性的“覆盖率百分比”。点开规则行显示状态对应的处理方向、固定来源类别和最近一次可用采样时间；采集器没有实际样本时间时明确显示“尚无可用采样时间”，不拿报告生成时间填充。组合状态会同时展示已计入的风险分和仍使总体保持待确认的缺项。来源经过白名单筛选，不携带路径、主机名或环境值。多来源证据摘要与采集时间线仍待接入。

## 阻断与数据不足

阻断文案示例：“已阻止启动：此会话的网络路径不符合你锁定的配置。”下方给出触发规则、目标域名、脱敏路径、时间与修复入口。

unknown 示例：“暂未允许启动：无法确认此会话出口。已关闭本次启动，修复后重试。”详情展示“已知扣分 11，安全分上限 89；2 项待检测”，主数字保留 `—`。

多项轻微扣分示例：“已阻止启动：当前 77 分，低于最低安全分 80。”列出机房 −8、VPN −6、IP/时区 −6、IP/语言 −3，不再要求附带严重网络异常才能退出。

代理口令、完整 token、项目路径、终端问题正文不进入弹窗或通知。IP 默认可遮盖，展开为本地操作。

桌面通知由用户在“数据与诊断”中主动开启；首次开启由 macOS 请求通知权限。同一段持续风险仅发一次状态通知，恢复为允许后发一条恢复通知，不按每次探测失败重复提示。通知正文不含 IP、代理配置、文件路径或会话内容。通知关闭、权限拒绝或系统通知不可用时，菜单栏和终端仍显示状态及原因。

脱敏诊断由用户在“数据与诊断”中主动选择保存位置，只导出 app/OS 版本、检查上下文、决策、安全分/上限、未知数量，以及规则 ID、状态、扣分和样本时间。过滤非目录规则与未知状态值；不导出自由文本原因、来源、建议、IP、环境、文件路径、进程/会话身份或启动票据。文件采用用户指定 JSON 位置并设置为仅当前用户可读写。

不默认设置“一键永久忽略”。高级用户可在已知启发式 finding 上建立带到期时间的例外，必须展示保护降级；适用范围不满足和数据未知不通过简单忽略伪装为安全。

## 设置窗口

从仪表盘打开独立设置窗口。左侧使用系统适配的侧栏表面、品牌盾牌和简短分区导航；右侧以清晰页面标题、说明和成组设置构成。标题区不用大写眉题和装饰色线。正文保持易读字号；窗口默认 1000×760pt，最小 900×660pt，允许用户调整尺寸，正文限制最大宽度并保留滚动区。

| 页面 | 内容 |
|---|---|
| 防护策略 | 启动最低安全分、运行中最低安全分、会话结束策略 |
| 网络与隐私 | Claude DNS flow 监测的启用状态与用户主动启停、System Extension/macOS 授权等待、系统 DNS Proxy 配置失败恢复、IPWho 地理查询授权、ProxyCheck 信誉查询独立授权、查询数据去向 |
| 受管会话 | 显示受管进程 PID、主/子会话类型、检查状态与分数；结束前明确确认，不显示聊天正文 |
| 数据与诊断 | 桌面状态通知、信誉 API key 钥匙串保存、网络历史保留/字段/权限披露与清除、脱敏诊断导出 |
| 受管会话 | 仅显示 PID、主/子会话类型、状态和安全分；允许用户请求结束会话，Agent 按 PID 与进程出生时间再次核验 |

会话页空状态、Agent 离线/刷新失败、检查中、受保护、处置中和结束失败均需明确呈现。IPC 不返回完整可执行路径、参数、工作目录或会话内容。

阈值提供键盘可达的步进按钮、明确范围和动作说明；运行中终止文案指出具体策略行为。设置保存失败、密钥保存失败与后台离线均以内联文字说明恢复方法。点击清除历史先展示本机影响确认。

DNS Proxy 是用户主动启用的系统级集成，不随 App 启动自动打开。页面显示未启用、等待 macOS 批准、正在保存配置、已启用和失败状态；启用确认说明其会处理本机 DNS flow、可能停用其他应用的 DNS Proxy，停用 SafeClaude 后需检查其他代理是否需要手动恢复。macOS 15 以下禁用启用操作并说明 D01–D04 仍待确认。扩展把目标 DNS flow 的 audit token、PID 启动代次、传输类型、适用的加密协议类别和脱敏 resolver 摘要写入 App Group 短期队列；Agent 仅接受与现有受管进程身份匹配的记录。D01 将已观测 resolver 与当前 SystemConfiguration 生效 resolver 集合比较；首次目标查询前仍为未知，匹配只表示符合当前配置，不构成持久锁定基线。D02/D03 已实现用户授权的解析器出口探测、IPWho 国家比较和保守未知状态；Akamai TXT 探测对 port 53 使用 UDP，对明确配置在标准 port 853 的 resolver 使用经过系统 TLS 信任校验的 DoT/TCP。系统明确提供且能与实际 resolver 唯一匹配的 DoH URL、服务器 IP 和 TLS 身份时，使用 HTTPS DNS-message POST；身份歧义、客户端证书配置、URL/路由未知或 TLS 验证失败均保持 unknown，不降级为裸 UDP。DoH/DoT/UDP 探测得到的递归出口 IP 只在内存中发送给 IPWho，短期 App Group 证据只保存国家码和解析器摘要。D04 按域名读取系统当前 DoH/DoT/明文设置，并按持久化策略要求 DoH 或 DoT 任一协议、仅 DoH 或仅 DoT；不符合策略会扣分，旧版未区分协议的证据仅满足“DoH 或 DoT”策略。会话基线及降级标记随 0600 SessionJournal 跨 Agent 重启保留；首次观测、路由歧义及策略要求的协议尚未被当前路由证明时继续阻断。策略在网络设置中选择并通过“保存网络设置”跨会话生效。

启用“允许 IPWho 地理查询”后，Agent 对 port 53 resolver 发起固定 Akamai `whoami` TXT UDP 查询，对标准 port 853 resolver 使用系统 TLS 信任校验的 DoT/TCP 查询；DNS 扩展对唯一匹配且无需客户端证书的系统 DoH endpoint 使用 HTTPS DNS-message POST。成功后取得递归解析器公网出口 IP，并发送该 IP 到 IPWho，仅在本机比较国家码。DoH URL、TLS 身份、服务器地址与当前 flow 必须能唯一对应；缺项或不匹配时保持未知，不做裸 UDP fallback。出口 IP 只在内存中用于查询，短期 spool 不写原始 IP 或 DNS 响应。关闭授权时不进行递归出口地理查询，D02 保持未知，多 resolver 情况下 D03 也保持未知并阻断。DoH/DoT TLS、递归 TXT 响应及在线 IPWho 行为仍待实测验收。

ProxyCheck 有独立的“允许 ProxyCheck 信誉查询”授权，默认关闭。开启后，Agent 将本次 Claude API trace 的出口公网 IP 发给 ProxyCheck v3，以取得代理、VPN、Tor、机房及信誉信号；关闭时完全跳过请求，相关证据保持 unknown 并依评分策略处理。无 key 可使用供应商按查询出口 IP 计数的每日额度；可选 key 仅改变供应商额度规则，授权仍由该开关控制。供应商隐私说明称匿名查询会记录查询方 IP 用于额度计数，带 key 查询方 IP 最多保留 24 小时。结果仅在本机内存按 IP、key 与路由隔离缓存，最长 15 分钟；不会持久化出口 IP 或供应商原始响应。

## 首次启动

1. 展示“安全分越高越安全；默认低于 80 阻断”，说明检测内容与数据去向。
2. 发现官方安装、版本、现有 wrapper/代理配置；显示检查结果。
3. 让用户选择受保护入口，展示 PATH 与 Claude 设置的具体增量；用户执行安装。
4. 通过系统流程启用 Agent/开机运行，展示真实授权状态。
5. 用本地模拟风险跑一次“会被阻断”的演练；不提交模型请求，不故意切换到危险网络。

安装确认是产品真实修改用户电脑的交互设计，不是本次编写方案的额外审批要求。

首次启用窗口展示 Claude Code 发现/选择、将写入的 shell 与 Claude 设置集成、用户级 Agent 服务状态和本机数据边界。只有 App 位于 `/Applications` 下才允许首次安装；App 中直接调用包内安装流程。登录启动由随集成安装的用户级 LaunchAgent 管理。卸载从 Agent drain 与受管会话复核开始，逐一撤销 DNS 扩展和特权校时服务，再校验并移除 shell/Claude 设置片段与用户级服务；特权 helper 在固定 MachService 上暂停采样并安全删除 root 校时快照后，安装器才清理用户集成。如果 XPC 或服务撤销失败，保留安装 bundle 并显示可恢复原因。

## 2026-11-14 设置控制台续修

保留品牌盾牌、青柠识别色和四个设置分区，并让侧栏与内容区随浅色、深色及增强对比外观变化。侧栏用中文分区名与 SF Symbols 导航；页面标题只显示分区图标、中文标题和说明，不使用英文 kicker。设置窗口默认 1000×760pt、最小 900×660pt，正文可滚动。STUN 地址、Claude executable 与信誉服务密钥输入使用统一输入组件，键盘焦点显示青柠描边。字段、导航名称、选项顺序和确认行为不变。

控制台页面使用开放式分组：主画布上以细分隔线、段落间距和操作行组织设置，不再把整页嵌入圆角容器；卡片只用于明确需要聚焦的单项状态或首次设置提示。受管会话改用横向列表行呈现进程、分数和操作。此处理为菜单栏主仪表提供视觉层级，并让长篇网络设置在滚动中保持章节关系。

首次接入窗口沿用分步控制台语言：用 `01`–`03` 对应选择 Claude、接入入口和安装前检查，依靠分隔线形成推进顺序；处理中/失败状态用短色标和内联说明，不为每个区块再套容器。状态行的辅助功能值会朗读状态解释，并在安装、升级或刷新时补充“当前正在处理”，不依赖颜色或旋转指示器单独传达忙碌状态。64 项报告移除英文大写眉题与胶囊筛选，分类使用文字加底部选中线，规则行仅在展开时获得表面强调，其余以细线连续分隔。

本轮系统截图只捕获到黑色登录屏幕，Computer Use host 连接应用超时。因此本次记录为源码审查和编译验收，不把该画面描述为视觉通过；仍需在已登录桌面检查页面密度、键盘焦点顺序与 VoiceOver。

## 终端体验

成功默认不输出防护文本，以免破坏管道与 JSON 流。拒绝时非交互 stderr：

```text
guard: launch blocked [ROUTE_UNVERIFIED]
无法确认此会话的网络路径。请打开菜单栏查看原因，修复后重试。
```

`guard status --json` 输出结构化状态；`guard doctor` 定位 shim、wrapper、版本与后台服务漂移。命令名称是设计示意，公开品牌确定后统一。

## 完整状态验收

需覆盖：首次无历史、采样中、允许、警告、已阻断、数据不足、断网、唤醒重验、检测源失败、来源冲突、多个上下文、未保护会话、Agent 停止、权限未批准、退出失败、恢复、配置冲突、规则待生效。

视觉验收包含系统深浅色、VoiceOver 读出“环境安全分 94 分，可以启动，48 项适用检查已完成”、键盘操作、200% 文本缩放/辅助功能字体，以及通知关闭后的替代反馈。设置页、规则报告和菜单栏面板的文字使用 SwiftUI 动态缩放度量，控件图标保持独立尺寸；菜单栏面板在辅助功能字号下增加宽高，为长文案和滚动内容保留空间。目标 App 的实际大号文字布局仍需实机验收。48 是界面示例，真实数字来自本次适用性评估。

## SafeClaude 品牌图标

正式应用标志采用「路径穿越盾牌」：酸橙绿折线路径在石墨底盾形中穿过，表示 Claude 启动路径接受环境审查。菜单栏使用同一符号的透明单色模板 PNG，由 macOS 按当前菜单栏外观着色，并保留文本分数与 VoiceOver 名称；Finder 使用石墨底的 AppIcon.icns。六个可编辑方向及小尺寸并排比较见 `docs/design/logo-concepts/index.html`。图标只用盾形轮廓与一条路径，避免在 16pt 菜单栏尺寸丢失细节。
